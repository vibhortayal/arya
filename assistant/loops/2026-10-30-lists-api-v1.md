# 2026-10-30 — Open Lists API v1

What changed
- New `/api/v1` sub-app (`api/routes/lists_v1.py`): lists, list with items,
  add (structured or text), PATCH and DELETE an item, export (csv, json,
  text), import (csv or text). Bearer token only (the connector's token),
  shared 600/h limit and 256 KB cap with the MCP connector, errors as
  `{error:{code,message}}`, public schema at `/api/v1/openapi.json`.
- `api/list/export.py`: the CSV/text layouts and parsers, pure functions.
  The in-app Share and Export can call them when it is built.
- `routes/lists.py`: no new logic. The bodies of from-text, remove, qty,
  move, check and list create moved into helpers the API calls
  (`_add_typed`, `_remove_item`, `_set_qty`, `_move_item`, `_set_checked`,
  `_create_list`). New items now carry `added_at`.
- `demo_guard.require_login`: `/api/v1` is bearer-only and answers 401 in the
  API error shape; the schema is public.
- Settings › Use Arya in another AI app: one line that the same code works for
  the Lists API. `docs/API.md` has curl examples.
- Add never moves an item from another list: it reports `also_on` instead.
  The in-app add still moves (UI thread owns that).

Tests: `tests/test_lists_api_v1.py` (29, all pass). Full suite on this
branch has the same 15 failures as main in this venv (sticker cutout, scanned
PDF, demo town reset, add surface); the venv lacks opencv and pypdfium2.
