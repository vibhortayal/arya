# 2026-11-02 Offline list changes (sync queue)

Owner, 2026-11-01: "i want offline add to queue". Reverses #323 for lists only. Offline, a person can add items by typing, tick and untick, edit, remove, and move or file items. Each change saves on the phone, shows at once, and syncs by itself when the signal is back. Receipts, Ask, voice, photo adds and whole-list changes (new, rename, delete) stay online-only.

- Server `api/listops.py`, middleware inside `require_login`, for POSTs to `/api/list/{add,remove,qty,edit,check,check-ok,move,also,aisle,from-text}` and `/api/items/{id}/flag`:
  - X-Arya-Op: an op id is applied once. Its answer is kept per account (newest 500, `list_ops.json`), and a replay gets the kept answer with `duplicate: true`. Two replays at the same moment: the second answers `duplicate`.
  - Last change wins per item: every applied write stamps the item (`list_changes.json`, a group doc so members share it). A queued change (X-Arya-Op-At, X-Arya-Op-Sent, ms) moves onto the server clock by `now - (sent - at)`, so a wrong phone clock still lines up (clamped to the last 7 days). A change older than the item's stamp is skipped with `{ok, stale: true}`.
- Client `lib/listQueue.ts`: `post()` sends list writes with an op id. It keeps the change (localStorage, per account, never the demo) when the phone is offline, when the send fails for want of a connection or times out, while older changes wait (to keep order), or when the change targets an item added offline (`local:` id). Reads of /api/home come back with waiting changes applied. `flush()` runs in order and maps local ids to real ones. 4xx drops the change (failed), 5xx retries up to 3 times, and a lost connection or 401 keeps everything. Event `arya-listq-synced` carries `{done, skipped, failed, skipped_names, failed_names}`.
- `app/listSync.ts`: sends on app open and on `online`, and toasts "Saved on this phone…" once per offline spell plus the sync result. `useListQueue()` gives `{pending, syncing}` for the UI thread's pending banner and the "waiting to sync" row mark (rows with `source: "queued"`). Those are mockups first.
