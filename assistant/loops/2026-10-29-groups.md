# 2026-10-29 — Groups (shared lists and receipts)

Owner asked: people in one household see the same lists and receipts,
with a way to leave. Owner rules: name it "Group"; on leave, lists are
duplicated, receipts stay with the account that filed them, and the
analysis (usage, patterns) recomputes. Wireframe approved:
https://claude.ai/artifact/1A8XKyKMozsUVxLNg88ADc. Owner said build the
full version (not the lists-only slice).

## What changed
- `api/state.py`: a store now resolves to a plane. In a group, the stores
  in `GROUP_DOCS` (lists, flags, cart, dictionary, judged, grocery
  verdicts, curator, second seat) read and write `data/groups/<id>/`
  (Postgres owner `group:<id>`; no new table). `receipts()` reads every
  member's receipts and tags each with `member`; `own_receipts()` is the
  account's own. Line fixes land in the filer's store; `add_receipts`
  will not file a receipt another member already filed.
- `api/groups.py`: registry in `groups.json` (data root). Create (the
  founder's lists become the group's), invite (6 letters, no 0/O/1/I/L,
  48 h, hashed, a new code replaces the old), preview, join (same-named
  lists merge, the joiner's items follow), leave (copy of every shared
  store; owner passes to the oldest member; last one out closes the
  group), remove (owner only), activity log for "Priya added Hummus".
- `api/routes/groups.py`: `/api/group*`. Wrong codes rate-limited per IP.
  Demo has no group. Deleting an account leaves its group first.
  Only the filer can delete a receipt (403 for others).
- Reminders run each account inside its group.
- PWA: `pwa/group.js` (Profile Group section, invite / rename / remove /
  leave sheets, Join a group screen, `/?join=CODE` links, Lists "shared
  with" line and who-changed-what on cards, refresh when the app comes
  back to the front). Receipts: who filed it, Everyone / Mine / person.
  SW arya-v83.

## Live sync (same day, PR after #121)
Owner asked for live sync, chose the scalable path, and noted Supabase is
already there.
- `api/live.py`: every save to a group's shared stores, every receipt a
  member files, and every join / leave / rename calls `live.changed(gid)`
  (hooked in `state._save` and `groups._signal`). With `DATABASE_URL`
  set it is `pg_notify('arya_group', …)` and one LISTEN thread per server
  process fans it out, so several processes stay in step; without a
  database, or with `ARYA_LIVE_PG=0`, it is delivered in-process.
- `GET /api/group/live`: Server-Sent Events, `change` events, a ping
  every 25 s, `left` when the caller is no longer in the group. Caps:
  2,000 streams per process, 6 per account. Only "something changed"
  is sent; the app reloads through the normal routes.
- App: `X-Arya-Client` tab id on every request so a tab skips its own
  echo; group.js opens the stream while the app is in front, reloads the
  open screen after 400 ms (waits while a field is being typed in),
  closes it in the background and catches up on return. The service
  worker leaves the stream alone. SW arya-v84.
- Caddy needs nothing: it flushes `text/event-stream` at once.
- Checked with two server processes on one local Postgres 16: a change
  on process 1 showed on a phone on process 2 in about 0.5 s; a tab's
  own add caused no extra reload. Tests: `tests/test_group_live.py`.
- Not tried against the Supabase session pooler yet (it supports
  LISTEN in session mode). If the pooler refuses, `ARYA_LIVE_PG=0` keeps
  sync working on the single VM process.
