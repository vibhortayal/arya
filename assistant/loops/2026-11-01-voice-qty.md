# 2026-11-01 Voice and Ask adds: quantity from words, no loose match

From the owner's iPhone test (live fa12c56): "Add oat milk and two lemons to my Costco list" added "Milk - 2%" and an item named "two lemons".

- Quantity: spoken number words one to twelve at the head of a piece become a count, the same as a typed "2 lemons" (intake `_lead`), so voice and typed adds in Lists give Lemons x 2. Ask adds read the count the same way and the Ask prompt now asks for `qty` on add_to_list. "one percent milk" stays a name.
- Wrong match: an Ask add used the loose token matcher, which treated "oat milk" as the tracked "Milk - 2%". Adds and "ran out" now use `existing_item_id` (the same strict match as the Add box), so only a name that is a tracked item joins it.
- Stale chat lines: the model re-emitted earlier adds because an actions-only turn was dropped from history. That is fixed in #395 (not in this PR; based on main, no stack).

Tests: tests/test_ask_qty.py. Python suite: same 18 failures as main (stickers, landing, etc.), +25 passing.
Not changed: names are kept as said ("lemons", not "Lemons"), like the Add box.
